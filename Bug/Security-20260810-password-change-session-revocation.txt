รายงานช่องโหว่: เปลี่ยนรหัสผ่านแล้ว session เดิมยังใช้ได้
สถานะ: VALIDATED (ตรวจ source แบบอ่านอย่างเดียว)
ระดับ: MEDIUM (CVSS ประเมิน 6.5)
หมวด: Insufficient Session Expiration (CWE-613)
วันที่: 2026-08-10

หลักฐาน
- apps/api/src/modules/users/users.service.ts:96-106 เปลี่ยน password hash แล้วคืน success โดยไม่ revoke session ใด
- apps/api/src/modules/auth/auth.service.ts:230-245 แสดงแนวทางที่ถูกต้องของ reset-password: update password พร้อม revoke ทุก active session
- apps/api/src/modules/auth/strategies/jwt.strategy.ts:25-39 จะยอมรับ token เดิมตราบใดที่ session ยังไม่ revoked และไม่ idle/หมดอายุ

ผลกระทบ
ถ้าผู้ใช้เปลี่ยนรหัสผ่านหลังสงสัยว่า token ถูกขโมย ผู้โจมตียังใช้ session/JWT เดิมทำ HTTP requests ต่อได้จนหมดอายุหรือถูก revoke ด้วยวิธีอื่น

การตรวจสอบอย่างปลอดภัย
เขียน integration test: login ด้วยบัญชีทดสอบ, เรียก change-password, แล้วเรียก endpoint ที่ต้องยืนยันตัวตนด้วย token เดิม; ผลที่คาดหวังคือ 401

คำแนะนำ
ทำ changePassword เป็น transaction ที่ revoke active sessions ทั้งหมด (หรืออย่างน้อยทุก session ยกเว้น session ปัจจุบันตามนโยบายที่ชัดเจน), แล้วออก token ใหม่ให้ session ที่อนุญาตเท่านั้น

สถานะการแก้ไข: Open — ไม่มีการแก้โค้ดในรายงานนี้
